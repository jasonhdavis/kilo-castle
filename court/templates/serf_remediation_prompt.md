## Remediation Protocol (Mandatory Steps)

1. **Investigate & Repair**:
   - Inspect the failing tests and code in this worktree (`{{ worktree }}`).
   - Fix the root cause without breaking existing functionality.
2. **Local Verification**:
   - Run the exact failing test command locally:
     ```bash
     {{ failing_test_cmd }}
     ```
   - Verify that all tests pass cleanly.
3. **Git Cleanliness, Rebase & Zero Roleplay Leakage**:
   - Run `git status --porcelain` and ensure no uncommitted files remain.
   - Run `git merge castle --ff-only` (or `git rebase castle`) to ensure `behind: 0`.
   - Ensure NO internal Court/Castle roleplay vocabulary (`Tribute`, `Serf`, `Kingdom`, `Ballad`, `Penance`, etc.) exists in any modified code, models, or UI templates.
4. **Bear Tribute Again**:
   - Prepare your 5-part completion report.
   - **Append** your fix notes to `Tribute Rendered` (`--append`):
     ```bash
     python3 -m court.cli set-section {{ quest_id }} "Tribute Rendered" --file <path_to_saved_report> --append
     ```
   - Notify the Steward so the Quest can be re-audited by the Master of Coin.

## Migration Collision Remediation (when the rejection is a migration conflict)

Apply this procedure when the rejection reason is a migration collision: your migration number collided with one already on `castle` (same-number git add/add), or `court collect`/the Gatekeeper flagged a quest-local merge migration on your branch.

1. **Absorb the trunk first**: `git merge castle --no-edit` so `castle`'s migration is present in your worktree.
2. **Schema migrations (autodetected deltas)**: delete your colliding file, then regenerate — `python manage.py makemigrations <app>` computes the next free number and dependencies from `castle`'s tip automatically. Verify with `python manage.py makemigrations --check --dry-run` (must exit 0).
3. **Data migrations (RunPython / custom operations)**: do NOT regenerate (autodetector cannot recreate them) — rename your file to the next free number and hand-edit its `dependencies` to point at `castle`'s current tip migration for that app.
4. **Semantically overlapping deltas** (both migrations add the same column/field — true duplicate work): do not renumber. DELETE your migration; your models already match `castle`'s, so `makemigrations` will generate nothing — that is success. Re-do only any part of your delta that `castle`'s version lacks.
5. **NEVER create `NNNN_merge_*` migrations inside a Quest worktree.** Merge nodes are trunk-owned artifacts generated by the Gatekeeper in the convoy; `court collect` mechanically refuses to pack branches carrying them.
6. Commit the excision/regeneration, note the renumber in your `Tribute Rendered` report, re-run your Quest's suite, and confirm `python manage.py makemigrations --check --dry-run` exits 0 before re-rendering tribute.
